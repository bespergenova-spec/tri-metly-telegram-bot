# Три метлы: Telegram-бот

Telegram-бот волшебного кафе «Три метлы». Гостей встречает мадам Розмерта: рассказывает о меню, ценах и графике, бронирует столики и проводит квиз Распределяющей шляпы. Бот написан на Node.js без внешних зависимостей, ответы генерирует бесплатная модель через [OpenRouter](https://openrouter.ai).

## Возможности

- Общение в образе мадам Розмерты. Характер, меню, цены и правила бронирования задаются в [system_prompt.md](system_prompt.md).
- Бесплатные модели OpenRouter с автоматическим переключением. Если модель отвечает ошибкой (например, 429), бот пробует следующую из списка.
- Приём картинок. Фото уходит модели, которая умеет их смотреть.
- Приём заявок на бронь через JSON: модель достаёт поля из сообщения, код проверяет их, переспрашивает недостающее и после подтверждения сохраняет заявку в `bookings.csv` (подробнее ниже).
- Напоминания о брони. Накануне визита в 12:00 по Астане гостю приходит сообщение от «совы».
- Постоянная клавиатура под полем ввода: меню, бронь, график и адрес, квиз.
- Квиз Распределяющей шляпы с кнопками ответов А, Б, В, Г.
- Админ-режим: уведомления о новых бронях и команда `/bookings`.
- История диалога: бот помнит последние 30 сообщений каждого чата (хранятся в памяти).

## Требования

- Node.js 20.6 или новее (нужен флаг `--env-file`).
- Токен бота от [@BotFather](https://t.me/BotFather).
- Ключ API OpenRouter.

## Установка и запуск

1. Клонируйте репозиторий и перейдите в папку проекта.
2. Создайте файл `.env` рядом с `index.js`:

   ```env
   TELEGRAM_BOT_TOKEN=токен_от_BotFather
   API_KEY=ключ_OpenRouter
   ADMIN_CHAT_ID=ваш_chat_id
   ```

3. Запустите бота:

   ```bash
   npm start
   ```

Устанавливать зависимости не нужно, `npm install` не требуется.

### Как узнать ADMIN_CHAT_ID

Запустите бота без этой переменной, напишите ему `/myid`, и он ответит вашим chat id. Впишите число в `.env` и перезапустите бота.

## Настройки (.env)

| Переменная | Обязательна | Описание |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | да | Токен Telegram-бота |
| `API_KEY` или `OPENROUTER_API_KEY` | да | Ключ OpenRouter |
| `ADMIN_CHAT_ID` | нет | chat id администратора: уведомления о бронях и команда `/bookings` |
| `MODELS` | нет | Модели для текста через запятую, по порядку приоритета |
| `VISION_MODELS` | нет | Модели, которые принимают изображения |
| `SYSTEM_PROMPT_FILE` | нет | Путь к файлу с промптом (по умолчанию `system_prompt.md`) |
| `TEMPERATURE` | нет | Креативность ответов, по умолчанию `0.6` |

Модели по умолчанию: `google/gemma-4-31b-it:free`, `google/gemma-4-26b-a4b-it:free`, `nvidia/nemotron-3-ultra-550b-a55b:free`, `nvidia/nemotron-3.5-super-vl:free`. Бесплатные модели иногда пропадают из каталога, актуальный список смотрите на [openrouter.ai/models](https://openrouter.ai/models?max_price=0).

## Как бот принимает заявку (JSON)

Когда гость пишет про бронь («хочу столик», «заявка», кнопка «Забронировать»), бот не просит модель вести весь разговор. Он делит работу на две части: модель понимает текст, а проверяет и решает код.

1. **Модель достаёт данные.** Сообщение гостя уходит модели с отдельным промптом из [extract_prompt.md](extract_prompt.md). Он требует вернуть только JSON с полями `intent`, `date`, `time`, `guests`, `name`, `phone` и `missing`. Если чего-то в сообщении нет, модель пишет `null` и ничего не выдумывает. Сегодняшнюю дату бот подставляет в промпт сам, потому что модель её не знает, а без неё не понять «завтра» или «в пятницу».
2. **Код разбирает ответ.** Если JSON не получился, запрос повторяется ещё один раз. Если и тогда не вышло, бот вежливо просит гостя написать заявку заново.
3. **Код проверяет данные.** Дата не в прошлом, время попадает в часы работы (бронь не позже чем за час до закрытия), в телефоне 11 цифр, гостей от 1 до 20. Если что-то не так, бот объясняет, что именно, и спрашивает это поле снова.
4. **Бот спрашивает недостающее.** Данные копируются между сообщениями, поэтому гость может отвечать по одному полю. Бот задаёт один вопрос про первое недостающее поле.
5. **Подтверждение.** Когда всё собрано, бот показывает итог и спрашивает «Подтверждаете?» (кнопки «Да» и «Нет, поправить»). Гость может и просто написать «да» или сразу прислать правку, например «время 20:00».
6. **Сохранение.** После «да» заявка записывается в `bookings.csv`. Заодно она попадает в `bookings.json`, чтобы работали `/bookings`, уведомление администратору и напоминание накануне визита.

Если модель решает, что сообщение не про бронь, бот выходит из режима заявки и отвечает как обычно. Отменить заявку можно словом «отмена» или командой `/cancel`. Окончательно бронь подтверждает администратор кафе.

## Что изменили примеры (few-shot)

В конец [system_prompt.md](system_prompt.md) добавлен блок `<примеры>` с тремя короткими диалогами: обычный вопрос, вопрос без ответа в данных и вежливый отказ. Все цены и факты в них взяты из самого промпта.

Пример работает как образец: модель видит, как именно нужно отвечать, и старается повторить. В [test_cases.md](test_cases.md) на пяти сообщениях видно, что изменилось:
- на вопросы без данных бот чаще сразу отправляет к администратору с телефоном;
- отказы стали короче;
- слова из примеров попадают в ответы (например, «медовуха»).

Но у примеров есть пределы. Метка `[уточнить]` в ответах не появилась, модель всё равно иногда выдумывает детали, а результат при каждом запуске немного отличается. Поэтому одних примеров мало: нужны ещё правила в тексте промпта и проверки в коде.

## Структура проекта

```
index.js              бот: Telegram, OpenRouter, брони, напоминания, кнопки
application.js        логика заявок: разбор JSON, проверки, CSV (без сети и Telegram)
application.test.js   тесты логики заявок (npm test)
system_prompt.md      промпт мадам Розмерты (легенда, меню, правила, квиз, примеры)
extract_prompt.md     отдельный промпт: достать поля заявки и вернуть JSON
test_cases.md         5 сообщений гостя: ответы бота до и после примеров
package.json          скрипты запуска и тестов
.env                  ключи (не попадает в git)
bookings.csv          заявки гостей (создаётся ботом, не попадает в git)
bookings.json         брони для /bookings и напоминаний (создаётся ботом, не попадает в git)
```

Тесты логики заявок запускаются командой `npm test`.

## Ограничения

- Бот работает, пока запущен процесс. При выключенном компьютере он не отвечает и напоминания не отправляются.
- Историю диалогов и недооформленные заявки бот хранит в памяти, после перезапуска они очищаются. Подтверждённые брони сохраняются в файлы.
- Бесплатные модели OpenRouter имеют лимиты на число запросов, поэтому иногда отвечают ошибкой 429. Бот в этом случае переходит к следующей модели.
- Ответы отправляются простым текстом без Markdown, разметка из ответов модели удаляется.
- Меню, цены, адрес и телефон кафе в промпте вымышленные.

## Комментарии к ДЗ 11

В реальном бизнесе не стоит передавать модели задачи связанные с несколькими условиями, отсутсвующими в правилах, утвержденных регламентах и связанных с деньгами, датами, и иными математическими вычислениями. Вопросы лежащие в плоскости общих правил и др. модель решить может. Пример, у нас есть проект HUB01, и мы утвердили правила партнерства и условия аренды. Потом к нам обратился партнер и предложил провести партнерское мероприятие в нашем зале без оплаты, где он может закрыть затраты на проведение мероприятия. В общем, над этим мы не думали и в регламенте этого не было. Такие не описанные случаи, которые не опираются на факты я бы включала с высоким рассуждением
